# Восстановление после неподтверждённой транзакции

Ошибка `unresolved_transactions=1` относится к постоянному реестру шлюза.
Новый торговый день и очистка таблицы QUIK не изменяют эту запись. Ошибка
`Instrument not found in QUIK` — отдельная проверка доступности инструмента.
Нельзя исправлять одну из них удалением всей базы.

## Диагностика

В PowerShell из каталога проекта:

```powershell
.\env\Scripts\python.exe -B -X utf8 diagnose_bot.py --settings settings_1.py
.\env\Scripts\python.exe -B -X utf8 recover_transaction.py --bot bot_1 --gid 1000000002
```

Первая команда использует отдельные порты 34990/34991, проверяет данные QUIK и
показывает незавершённые транзакции. Не регистрирует торгового бота и не отправляет
торговых команд. Вторая только читает выбранную запись SQLite; может выполняться
при работающем шлюзе. Никакого автоматического сброса по пустой таблице нет.

## Ручное закрытие старой неопределённости

Применять только после сверки доступной истории, текущих заявок и фактических
позиций в QUIK/у брокера. Если результат удалось установить, нужно сохранить
фактический результат; этот инструмент не предназначен для маскировки известной
заявки или отказа. Если результат старой транзакции установить нельзя, оператор
может явно принять решение продолжить с текущими позициями, сохранив неопределённый
результат в истории. Это не подтверждение того, что заявка была отклонена.

1. Остановить всех ботов через Ctrl+C, дождаться завершения отмены их заявок.
2. Выполнить stop_gateway.bat. При подключённых ботах шлюз остановиться не даст.
3. Проверить выбранную запись командой просмотра выше.
4. Только если принимается решение снять эту конкретную блокировку, выполнить:

```powershell
.\env\Scripts\python.exe -B -X utf8 recover_transaction.py --bot bot_1 --gid 1000000002 --close-stale --acknowledge-unknown-outcome --reason "Reviewed orders and positions; accept the unknown historical outcome"
```

Команда откажет при работающем шлюзе, активных заявках в реестре, возрасте менее
24 часов, другой московской дате в будущем/сегодня, известном номере заявки,
другом боте, другом состоянии/типе или найденной в реестре заявке с этим trans_id.
Команда не заменяет проверку фактических заявок и позиций в терминале.

Результат: только выбранная запись меняется с uncertain на closed_unknown.
В runtime/recovery сохраняется резервная копия базы, в transaction_resolutions —
исходная запись, причина, оператор, время и SHA-256 копии. Запись и история
остальных ботов сохраняются. Сам робот не запускается; исходная транзакция
не отправляется повторно. После следующего запуска стратегия работает с
фактической позицией и сохранённой базой, а не с предположением о нулевой позиции.

Если FUTSPREAD или нужный инструмент недоступен в QUIK, сначала восстановить
доступность данных/сверить коды. Ручное закрытие транзакции это не исправляет.
Существующий state.txt не удалять для обхода проблемы. Демо- и боевые настройки
различаются только параметрами и подключённым терминалом.

## Перенос обновления на сервер

`git pull --ff-only` обновляет код; локальные settings_N.py и runtime исключены
из Git и сохраняются. Команда восстановления работает с локальной базой сервера.
Не копировать вместо неё базу с другого компьютера. Новые возможности логирования
и миграция request вступают в силу после перезапуска шлюза.
